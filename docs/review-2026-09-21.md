# Review of the deep-dive, 2026-09-21 — findings and work order

An audit of everything [`deep-dive-brief.md`](deep-dive-brief.md) delivered
across its six phases, and the work order that follows from it. Written to be
picked up cold: **read `CLAUDE.md`, then this file, then work the checklist.**
Nothing here has been fixed yet.

Every finding below was reproduced against the files on disk — by running the
code, or by opening the cited line. Each carries the command that re-derives it,
so nothing has to be taken on trust, including this document.

## What the audit found

The infrastructure is sound. The round-trips, the corpus, the write guards, the
`validate` baselines and the reference agent's citations were all checked
first-hand and are exactly as the brief claims. **Do not re-verify these** — the
table under [Already verified](#already-verified-do-not-redo) records what was
run.

Two clusters of defects came out of it:

- **`ttslib` and its demo carry six runtime bugs** ([A1](#a1)–[A6](#a6)), two of
  which break a promise a module header makes in writing, and one of which is
  visible the sixth time you click the demo's main button. This is the layer the
  owner's prototypes are meant to stand on, so it ranks first.
- **A tail of wrong numbers in the documentation** ([B](#b--documentation-errors)).
  Small individually — but three are wrong *by the counting rule the same
  document mandates*, and one whole class quotes a mod's corpus-wide line total
  as a single file's length.

## A. `ttslib` runtime bugs

This is the layer the owner's prototypes are meant to stand on, so it ranks
above the documentation errors.

> **Fixed on 2026-09-21, except [A8](#a8).** A1–A7 each have a regression case in
> `test/ttslib_spec.lua` (A6's is in `test/demo_spec.lua`); A1, A4 and A5 were
> confirmed to fail against the pre-fix code by re-breaking it in a scratch copy
> and watching those cases go red. The descriptions below are kept as the record
> of what was wrong and why each fix is shaped the way it is. **[A8](#a8) is
> still open** — it needs a test inside TTS.

<a id="a1"></a>
### A1 — `events.dispatch` crashes if a handler unsubscribes itself

`reference/framework/ttslib/04-events.lua:112-114` iterates `for i = 1, #list`,
with the bound fixed at loop entry, while `E.off` (`:81`) does
`table.remove(list, i)`. A handler that unsubscribes during its own dispatch
shrinks the list, and the next iteration indexes past the end.

`E.dispatch` is itself **not** wrapped in `LOG.attempt` — only the individual
`sub.fn` calls are (`:121`) — so the error escapes `onObjectDrop` into TTS and
every later subscriber is skipped. "Subscribe, fire once, unsubscribe" is the
first thing anyone tries.

```bash
cd reference/framework && luajit -e '
local out = print
local H = dofile("test/harness.lua")
local lib = H.reset("ttslib")
local E = lib.events
local h; h = E.on("drop", "*", function() E.off("drop", h) end)
E.on("drop", "*", function() end)
local ok, err = pcall(function() E.dispatch("drop", "Blue", H.object({tags={"x"}})) end)
out("ok=" .. tostring(ok) .. "  " .. tostring(err))'
# ok=false  ttslib/04-events.lua:114: attempt to index local "sub" (a nil value)
```

**Fix:** iterate backwards, or snapshot `list` before the loop.

<a id="a2"></a>
### A2 — `events.offAll()` permanently disables the registry's cache invalidation

`05-registry.lua`'s `hook()` sets `hooked = true` and never resets it, while
`E.offAll()` (`04-events.lua:87-93`) sets `subscriptions = {}`, deleting the
registry's own `spawn`/`destroy` subscriptions. Nothing re-registers them, so
`reg.all`/`reg.one` return stale results from then on, with no warning.

`05-registry.lua:22-24` states in writing that "this cache invalidates itself on
spawn and destroy", and `offAll` is documented public API in
[`framework.md`](framework.md).

```bash
cd reference/framework && luajit -e '
local out = print
local H = dofile("test/harness.lua")
local lib = H.reset("ttslib")
local R, E = lib.registry, lib.events
H.object({tags={"wood"}}); out("warm cache: " .. #R.all("wood"))
E.offAll()
H.object({tags={"wood"}}); out("after offAll + spawn: " .. #R.all("wood") .. "  (want 2)")
R.invalidate();            out("after manual invalidate: " .. #R.all("wood"))'
# warm cache: 1 / after offAll + spawn: 1  (want 2) / after manual invalidate: 2
```

Run the same sequence without the `offAll` line as a control: it goes 1 → 2
correctly.

**Fix:** reset `hooked` in `offAll`, or have the registry re-hook lazily on each
query.

<a id="a3"></a>
### A3 — `layout.takeTo{tag=…}` leaves the registry stale

`06-layout.lua:216` calls `obj.addTag(opts.tag)` inside the `takeObject`
callback with no `REGISTRY.invalidate()`. TTS fires no event for a tag change,
and the spawn invalidation has already happened by the time the callback runs —
so a role assigned this way is invisible to `reg.all` until something unrelated
invalidates the cache.

[`framework.md`](framework.md) tells the *user* to call `reg.invalidate()` after
changing tags by hand; the library then changes tags itself without doing so.
`test/ttslib_spec.lua:561-567` sets this case up but asserts
`placed.hasTag("inplay")` on the object directly, so it cannot see the bug.

**Fix:** `REGISTRY.invalidate()` after `addTag`, and change that spec case to
assert through the registry.

<a id="a4"></a>
### A4 — `onObjectRotate` silently loses its last two arguments

`04-events.lua:146` forwards 4 of 6 arguments, and `LOG.attempt`
(`00-log.lua:103`) caps at four — its comment claims four "covers every TTS
event signature", which `reference/api/events.md:89` contradicts:

```
onObjectRotate(object, spin, flip, player_color, old_spin, old_flip)
```

A rotate handler almost always wants the *delta*, so `old_spin` is the argument
you reach for. This falsifies `04-events.lua:16-19`, which promises handlers
receive "TTS's own arguments, in TTS's own order".

**Fix:** widen `LOG.attempt` and the dispatch chain to six arguments.

<a id="a5"></a>
### A5 — `layout.place{facing=…}` silently flattens X and Z rotation

`06-layout.lua:160` builds `{ x = 0, y = …, z = 0 }`, discarding the object's
existing rotation on the other two axes — so placing a face-down card or a
flipped tile with `facing` turns it face-up.

```bash
cd reference/framework && luajit -e '
local out = print
local H = dofile("test/harness.lua")
local lib = H.reset("ttslib")
local L = lib.layout
H.object({tags={"board"}, position={x=0,y=1,z=0}})
local card = H.object({tags={"c"}, rotation={x=0,y=0,z=180}})
L.anchor("board"); L.spaces({ slot = {0,0,0} })
L.place(card, "slot", { facing = 0 })
local r = card.getRotation()
out(string.format("x=%.0f y=%.0f z=%.0f  (started z=180)", r.x, r.y, r.z))'
# x=0 y=0 z=0  (started z=180)
```

**Fix:** preserve the object's current X/Z, or document the flattening and add a
`keepTilt` option.

<a id="a6"></a>
### A6 — the demo stacks two cubes: six in the bag, five clearing slots

`demo/Global.lua:54` sets `SLOTS = 5`; `:79-81` computes `slot(index)` as
`index % SLOTS`; `:134` calls it with `woodInSupply()` — the count *before* the
take. `demo/objects/supply.json` holds **6** cubes. Six clicks of "Take wood"
therefore place the sixth cube exactly on top of the first.

This is the artifact both [`framework.md`](framework.md) and
`reference/framework/demo/README.md` tell the reader to load first, and that
README's "Try it" step 1 invites repeated clicking.
`test/demo_spec.lua:177-185` clicks once and asserts only the object count.

```bash
python3 -c "import json; d=json.load(open('reference/framework/demo/objects/supply.json')); print(len(d['ObjectStates'][0]['ContainedObjects']), 'cubes')"
grep -n 'SLOTS = ' reference/framework/demo/Global.lua
```

**Fix:** `SLOTS = 6`, or index by cubes-taken rather than cubes-remaining. Then
extend the spec to drain the bag and assert six distinct positions.

### A8 — two comments give opposite instructions, and the corpus cannot settle it

`03-ui.lua:157` says of `unscale`: "Pass this as `scale`, **and divide positions
by the same factors**." `demo/Global.lua:169-171` deliberately does the opposite
and says so: "positions stay in the same local units the spaces table uses."

One of them puts every button at a fraction of its intended offset on the demo's
6 × 1 × 4 board. `reference/api/object.md` documents `createButton`'s `position`
only as "relative to the Object's center" and never says whether it is pre- or
post-scale, so the corpus cannot decide this.

**Fix:** until it is tested in TTS, add it as **open question #4** in
[`cookbook/10-antipatterns.md`](cookbook/10-antipatterns.md#open-questions-test-these-in-tts)
with a two-minute test, and make the two comments agree that it is unsettled.

### B4 — `docs/framework.md:112` overstates what the log module reaches

It reads: "`trace` and `debug` go to the host System Console (`~`), everything

## C. Tooling gaps

> **C1 and C2 fixed on 2026-09-21.** Of [C3](#c3), only the first and third
> bullets are addressed — both spec runners now report a thrown case through
> `out` instead of the rebound `print`, and `H.object`'s auto-spawn is called
> out here. **The coverage gaps in C3's last bullet remain open**, except
> `rotate`, `offAll` and `waitFor`, which the new regression cases now exercise.

<a id="c1"></a>
### C1 — `deck build` accepts a sheet larger than the `CardID` encoding allows

`cmd_deck_build` (`scripts/tts.py:1359`) validates `--cols`/`--rows` ≥ 1,
`--count` ≤ slots, `--count` ≥ 2 and `--sheet` ≥ 1, but never bounds
`cols * rows`.

`CardID = sheet * 100 + index` with a zero-based index — the rule its own
docstring says it honours — caps a sheet at 100 slots. Above that, IDs decode to
the **next** sheet: `--cols 11 --rows 10` on sheet 1 yields `CardID` 100…209,
and everything from 200 up reads as sheet 2. `validate` does not catch it.

Every real sheet in this folder is ≤ 49 slots (largest: 7×7), so this is a
missing input guard rather than a live bug.

**Fix:** `die()` when `cols * rows > 100`, naming the rule.

<a id="c2"></a>
### C2 — `validate` exits 1 on warnings, and `demo/build.sh` runs under `set -e`

`cmd_validate` calls `sys.exit(1)` whenever findings exist, warnings included —
WARN-only input exits 1, clean input exits 0. `reference/framework/demo/build.sh:14`
sets `set -euo pipefail`, and `:48` runs `tts validate "$OUT"` before the
`built $OUT` confirmation at `:51`.

The demo validates clean today, so the build passes. But any future change
raising a single WARN makes the build *appear* to fail after having written a
perfectly good save.

**Fix:** exit **2** on ERROR, **0** on WARN-only. Keep "clean vs. has findings"
visible in the output; a warning is not a failure.

<a id="c3"></a>
### C3 — the test suite cannot see the bugs in the module it covers most

- **The runner swallows the message for any case that throws.**
  `test/ttslib_spec.lua:637` and `test/demo_spec.lua:331` use bare `print` for
  the ERROR line, and `test/harness.lua:457` rebinds `print` into `H.printed`.
  Both files capture `local out = print` at the top for exactly this reason and
  then don't use it on the one path that matters. A thrown case bumps the
  failure count and tells you nothing.
- **The stub fakes away what `ui` depends on.** `harness.lua:255` makes `setVar`
  a plain table write, and the click tests then call `Global.getVar(fname)(…)`
  by hand — asserting that ttslib put the function where ttslib said it would.
  TTS's actual `click_function` name resolution, the premise of the whole
  module, is never modelled. Note that `setVar` storing a **function** is
  undocumented: `reference/api/object.md:478` is its only mention and says only
  "cannot set a table". This is the one call in `ttslib` that loading
  `TS_Save_126` must confirm.
- **`H.object` auto-spawns** (`harness.lua:332`, `if spec.spawn ~= false then
  H.spawn(obj) end`), so `H.spawn(H.object(…))` double-registers. Worth a line
  of comment; it costs everyone who writes a scratch test one wrong result.
- **No coverage at all** for `ui.xml/attr/attrs/show/hide/clear/panel/env`,
  `async.after/cancelAll/forget`, `events.count/offAll`, `store.get/clear`,
  `registry.roles`, `layout.space/vec`; for 8 of the 13 events (one `rotate`
  case would have caught [A4](#a4)); and `ObjectScript.lua` is never loaded by
  either spec, so `ui.env()`'s `self` branch has never executed.
