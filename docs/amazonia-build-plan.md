# Amazonia — build plan for a hex-tile prototyping rig

**Status:** built and running, 2026-09-21. Both in-game gates passed; the only
thing left is the owner's own look at the tiles. **Written 2026-09-21.** The rig
is [proto/amazonia/](../proto/amazonia/README.md) and `Saves/TS_Save_127.json`.
§11 records what was built and where it departs from this brief; **§12 records
what the gates found, including a correction to §2.2's protocol.**

This is a self-contained implementation brief. Every measurement in it was
taken from this folder and re-verified; you should not need to re-derive any of
it. Where a number is load-bearing, the command that produced it is given so
you can re-check cheaply rather than trusting prose.

Read [CLAUDE.md](../CLAUDE.md) first for the folder's safety rules. The ones
that bind this work:

- **Never modify a save in place.** New work goes to `Saves/TS_Save_127.json`
  and up. Re-check the highest number before writing — 126 was the highest on
  2026-09-21.
- **Never `Read` a save file directly.** Use `scripts/tts.py`.
- **`Mods/` is read-only.** This plan reads two cached assets from it and
  writes nothing.
- **Check TTS is not running** before writing under `Saves/`
  (`ls -lt Saves | head`).

## 1. What is being built, and why

The owner is prototyping an Amazonian-jungle board game whose map is laid out
at setup from **tiles that group three hexagons together**, in the style of
Railways of the Lost Atlas (RotLA) and Clash of Cultures. Tiles must be
recolourable (green, dark green, …) and carry resource-hub markings ("this tile
harvests rubber").

The deliverable is **not one save**. It is a rig: a loadable save that already
has tiles on the table, plus an interface for iterating on those tiles. Three
requirements the owner stated explicitly:

1. **Fewest possible tokens per iteration.** Prototypes should churn. This is
   why the External Editor bridge (§2.2) exists in the design at all — it makes
   a tile tweak one line out and one line back, with no rebuild and no save
   parsing.
2. **A change log.** The owner will move cubes and pieces by hand between runs
   and does not want to dictate what changed. The rig observes it (§5).
3. **Flexibility.** The tile *system* matters more than any one tile.

Design decisions the owner already made, which are settled and not to be
relitigated:

| Question | Answer |
| --- | --- |
| Tile shape | Three hexes fused into one tile |
| Art source | Generated by a stdlib Python script |
| Map layout | Random draw from a pool, re-rollable |
| Resource hubs | Lua buttons on the tile face |

## 2. Measured constants

### 2.1 The tri-hex mesh — RotLA's actual geometry

RotLA's map tiles are `Custom_Model` objects, **not** tiles. Verified:

```bash
python3 scripts/tts.py get Saves/TS_Save_122.json 'ObjectStates[330]'
```

```json
{ "GUID": "f664f7", "Name": "Custom_Model",
  "Transform": { "posY": 1.031499, "rotY": 180.0,
                 "scaleX": 1.0, "scaleY": 0.5, "scaleZ": 1.0 },
  "GMNotes": "8",
  "Locked": true, "Grid": true, "Snap": true, "Sticky": true,
  "CustomMesh": {
    "MeshURL":     "https://steamusercontent-a.akamaihd.net/ugc/2059887766546230341/BCC224366649AF522045FB3FD8B4561B531C90F3/",
    "DiffuseURL":  "https://steamusercontent-a.akamaihd.net/ugc/2059887766546230692/BCBD554AE1FFC410DCA4935639AAD59A1F1A97D8/",
    "ColliderURL": "https://steamusercontent-a.akamaihd.net/ugc/2059887766546230451/0FA340FD896779B56E394CB503792C371138AE5C/",
    "Convex": true, "MaterialIndex": 3, "TypeIndex": 0, "CastShadows": true } }
```

**61 objects in the mod share that one `MeshURL`.** Only `DiffuseURL` and
`GMNotes` (the printed tile number) differ. Clash of Cultures is built the same
way — one shared mesh across all region tiles and the four Start Tiles.

The cached mesh is at
`Mods/Models/httpssteamusercontentaakamaihdnetugc2059887766546230341BCC224366649AF522045FB3FD8B4561B531C90F3.obj`
(5,074 bytes, 72 verts / **24 unique** = 12 top + 12 bottom). Measured:

| Property | Value |
| --- | --- |
| Bounding box | **3.4642 × 0.2 × 3.5** (x, y, z) |
| x range | −1.7321 … +1.7321 (= ±√3) |
| y range | −0.1 … +0.1 (half-thickness 0.1) |
| z range | −0.9984 … +2.5016 |
| Circumradius R | **1.0** |
| Hex centres | `(0, 0)`, `(−√3/2, 1.5)`, `(+√3/2, 1.5)` — a triangle |
| Silhouette | a **12-gon with 3 reflex notches** |

The whole mesh carries a +0.0016 offset on z (a Blender rounding artefact);
treat the pivot as **hex A at the origin**. The pivot being at one hex centre
rather than the centroid is what lets `rotY ∈ {0,60,120,180,240,300}` interlock
up- and down-pointing tiles on a single lattice.

The 12 top-face outline points, exactly as measured (subtract 0.0016 from z for
the idealised form):

```
  -1.7321  1.0016     -0.8660 -0.4984     -0.8660  0.5016  *
  -1.7321  2.0016     -0.8660  2.5016      0.8660  0.5016  *
   0.0000 -0.9984      0.0000  2.0016  *   0.8660 -0.4984
   1.7321  1.0016      1.7321  2.0016      0.8660  2.5016
```

`*` marks the three reflex (notch) vertices. Exactly one vertex is fully
interior and therefore absent: `(0, 1.0016)`, shared by all three hexes.

Reproduce with:

```bash
python3 - <<'EOF'
F="Mods/Models/httpssteamusercontentaakamaihdnetugc2059887766546230341BCC224366649AF522045FB3FD8B4561B531C90F3.obj"
vs=[tuple(map(float,l.split()[1:4])) for l in open(F) if l.startswith('v ')]
u=sorted(set((round(x,4),round(y,4),round(z,4)) for x,y,z in vs))
print(len(vs),'verts',len(u),'unique')
xs,ys,zs=[[p[i] for p in u] for i in (0,1,2)]
print('bbox %.4f %.4f %.4f'%(max(xs)-min(xs),max(ys)-min(ys),max(zs)-min(zs)))
EOF
```

**The collider** is the same silhouette inset ~0.05 (bbox 3.3648 × 3.3832), so
neighbouring tiles do not physically fight.

**The UV rule.** The diffuse is `1000 × 1011` px, aspect **0.9891**; the mesh
bbox aspect x/z is 3.4642/3.5 = **0.9898**. They agree to 0.07%, which fixes
the mapping: **planar projection from above, normalised to the bounding box.**
Generate to that rule.

> **Do not confuse these with RotLA's 191 `Custom_Tile Type 1` hexes.** Those
> are its 18xx *track* tiles, dropped on top of a tri-hex at y ≈ 1.081 with
> `scale 0.98` so they nest inside one printed hex. That is a useful mechanism
> if the game later needs to overlay something on a single hex of a tile, but
> it is not the map.

### 2.2 The External Editor API — the live channel

Fully specified in `reference/api/externaleditorapi.md` (198 lines). Read it
before writing the bridge; do not guess the protocol.

- **TTS listens on TCP 39999.** You send it JSON.
- **Your process must listen on TCP 39998.** Replies do **not** come back on
  the request connection (`:129`).

Messages you send:

| ID | Name | Note |
| --- | --- | --- |
| 0 | Get Lua Scripts | |
| 1 | Save & Play | **Reloads the save.** Sending `script` without `ui` *deletes* the UI XML (`:161`). Always send both. |
| 2 | Custom Message | Arrives in Lua as `onExternalMessage`. Payload **must be a table** or the event does not fire (`:175`). |
| 3 | **Execute Lua Code** | `{"messageID":3,"guid":"-1","script":"…"}` |

Messages TTS sends you:

| ID | Name |
| --- | --- |
| 2 / 3 | print / error |
| 4 | Custom message from Lua's `sendExternalMessage` |
| 5 | ~~Return value from an ID-3 call~~ — **never sent by v14.2.2, see below** |
| 6 | **Game Saved** — carries an undocumented `savePath` |
| 7 | Object Created |

> **Correction, measured 2026-09-21 against the live game: TTS v14.2.2 never
> sends message ID 5.** An ID 3 *executes* — a `print` in it comes back as an
> ID 2 and a `broadcastToAll` shows on the table — but `return true`,
> `return 42`, `return "text"`, `return {1,2}`, `do return 9 end` and
> `return (function() return 7 end)()` each produced no reply whatsoever, while
> an ID 0 answered normally seconds later on the same listener. The "Return
> messages" section of `externaleditorapi.md` documents a feature this build
> does not have.
>
> `ttsd.py` therefore wraps every `exec` so the value comes back as a marked
> `print`, and still accepts an ID 5 if a later build restores it. The wrapper
> also `pcall`s the script, so a Lua error answers the call that caused it
> instead of arriving as an unattributable ID 3. See `ttsd.wrap_script`.
>
> ID 6 also carries `savePath` (with doubled separators,
> `/Users/artur//Library//Tabletop Simulator//Saves/TS_Save_127.json`), which is
> better than guessing the file from mtimes. Undocumented; the daemon uses it
> and falls back to the newest numbered save.

**`guid: "-1"` (Global) is mandatory** for ID 3. Per `:191`, executing against
any other object requires that object to already have a script open in the
in-game editor, otherwise TTS errors with *"Object reference not set to an
instance of an object"*. Global always has a script.

**There is no file I/O in TTS Lua** — `io`, `os.execute`, `dofile`, `require`
are all absent from the sandbox (`reference/api/lua-in-tabletop-simulator.md:27-44`;
only `OS_Time`'s four time functions are present). So 39999 is the *only*
inbound path; `WebRequest` is outbound-only and host-only.

Nothing in `scripts/tts.py` implements this — it has no socket code at all.
The folder's own docs cite the API three times as the unimplemented path
(`docs/cookbook/01-architecture.md:263`, `docs/critique.md:403`,
`docs/framework.md:85`).

### 2.3 Colour and runtime mutation

| Fact | Source |
| --- | --- |
| `ColorDiffuse` (`setColorTint`) works over a custom texture — **2,137 attested objects** in this folder. Multiplicative, so it darkens and shifts but never brightens past the source pixel. RotLA tints its hexes olive `{0.533, 0.604, 0.337}`. | corpus scan; `docs/save-format.md:75` |
| `setCustomObject` + **`reload()`** swaps a `Custom_Model`'s `diffuse` at runtime. `reload()` **destroys and respawns** the object — the old Lua reference dies, and it is not usable on the same frame. | `reference/api/object.md:1494`, `:1863` |
| The working exemplar for exactly this, on a `Custom_Model`: `getCustomObject` → mutate `.diffuse` → `setCustomObject` → tint → `reload()` → re-assert flags one frame later. | `reference/mods/arcs/global/src__SetupControl.lua:1112-1134` |
| `spawnObjectData` sets `CustomMesh`, `ColorDiffuse`, `Tags`, `Transform` in one call with **no reload**. Preferred for bulk spawn. | `reference/api/base.md:373-404` |

**Consequence for the design:** tint is free and instant; a texture swap costs a
respawn. That asymmetry is what produces the loop tiers in §6.

### 2.4 The `Grid` enum — resolved

The folder previously documented this as unknown. **Save-JSON `Grid.Type` is
0-based against the Lua `Grid` API enum: `JSON = Lua − 1`.**

| JSON `Type` | Meaning | Evidence |
| --- | --- | --- |
| 0 | Rectangles | 47 of 56 mods; what `tts.py new` writes |
| 1 | Horizontal hexes = **flat-top** | Shikoku 1889, The Old Prince 1871, Cloudspire, Heat |
| **2** | Vertical hexes = **pointy-top** | **RotLA**, CoC ME Extended |

Orientation was confirmed from mesh vertices (RotLA's verts sit at `(0, ±1)`,
i.e. points along z = pointy-top) and cross-checked against Shikoku 1889, whose
`Type 1` tile lattice measures `(±1.5R, ±√3R/2)` = flat-top.

RotLA's block, identical in the mod and both saves:

```json
{ "Type": 2, "Lines": false, "Opacity": 0.75, "ThickLines": false,
  "Snapping": false, "Offset": true, "BothSnapping": false,
  "xSize": 2.0, "ySize": 2.0, "PosOffset": {"x":0.0,"y":1.0,"z":0.0} }
```

`xSize`/`ySize` are always equal and equal the hex's **across-corners diameter
(2R)**. With `Lines:false, Snapping:false` the grid is **declared but inert** —
it documents the geometry rather than enforcing it. Do the same; snap points do
the real work.

`tts.py new` always writes `Type 0` and has no `--grid` flag, so `build.sh`
must patch `Grid` after the `new` step.

### 2.5 Placement — copy Clash of Cultures, not RotLA

RotLA has **no hex coordinate math at all** in 2,453 lines; its modular map is
built by hand by the players (`reference/mods/rotla/global/script.lua:895`
broadcasts "Create the map starting with Player N"). `grep -rn -i hex
reference/mods/` over all five corpora returns only Arcs' `color_to_hex`.

Clash of Cultures does it properly — tagged snap points on a locked board,
resolved through `positionToWorld`
(`Mods/Workshop/3059100548.json` `ObjectStates[174]`):

```lua
function setupRegions()
  local map = _G["map"]
  for i, snap in ipairs(map.getSnapPoints()) do
    if snap.tags[1] == 'region' then
      regionDeck.takeObject({
        position          = map.positionToWorld(snap.position),
        rotation          = snap.rotation,
        callback_function = function(o) o.setLock(true) end,
        smooth            = false })
    end
  end
end
```

`positionToWorld` rather than arithmetic is necessary there because the board
carries `WidthScale 1.1352`. Its snap lattice measures neighbour vectors of
length 3.444 at a √3 ratio — the index-3 hex sublattice, which is the
signature of a 3-hex tile, independently confirming CoC's tiles are tri-hexes
too.

**Adopt this pattern.** It survives moving or rescaling the board, and it gives
the owner hand-placement for free.

## 4. Components

### 4.1 `scripts/tilegen.py` — mesh and art minter (stdlib only)

Reads `spec/tiles.json`. Emits, per tile *shape*, a mesh and collider; per tile
*kind*, a diffuse.

- **Mesh** — a fused tri-hex prism to the §2.1 geometry: R = 1.0, hex centres
  `(0,0)`, `(−√3/2, 1.5)`, `(+√3/2, 1.5)`, half-thickness ±0.1, pivot at hex A.
  Compute the union of the three hex outlines into the 12-gon (3 reflex
  vertices), extrude, triangulate, and emit planar-from-above UVs normalised to
  the bbox.
- **Collider** — the same silhouette inset 0.05, as RotLA does.
- **Shape is a spec field**, so `hex1` and `hex3_line` cost one entry each later.
- **Diffuse — greyscale by default, following RotLA.** Value-noise grain, a
  darker edge band, and cell subdivision lines so the three hexes read as
  three. **Colour comes from `ColorDiffuse`, not the PNG.** That is what makes
  "make it dark green" an L1 tint call rather than a regenerate. A `per_cell`
  spec field bakes distinct colours into the three cells when a tile needs
  mixed terrain; such kinds drop to L2.
- **Content-hashed filenames** — `trihex-a1b2c3d4.obj`. This is load-bearing:
  TTS caches by mangled URL (`docs/asset-cache.md:94-101`), so reusing a
  filename risks TTS serving a stale asset. A new hash is a new URL and always
  reloads.
- Emits `art/index.json`: kind → `file:///…` URLs + sha256. Deterministic —
  same spec, same bytes, same names.
- `--check` regenerates and asserts hashes are unchanged.

### 4.2 `scripts/ttsd.py` — the bridge

Stdlib `socket`/`json`/`threading`. Two roles in one file.

Client verbs — one line in, one line out:

```bash
python3 scripts/ttsd.py exec 'return Map.count()'     # messageID 3, guid "-1"
python3 scripts/ttsd.py call tint jungle 2E6B33       # sugar over exec
python3 scripts/ttsd.py log --since last              # rendered changelog
python3 scripts/ttsd.py push                          # messageID 1, both fields
```

`exec` must hold a listener on 39998 for the ID-5 reply (§2.2).

Daemon (`ttsd.py serve`): holds 39998, appends every inbound message to
`.journal/events.jsonl`, and on **ID 6 (Game Saved)** runs `tts.py diff`
between its snapshot and the newest save, renders a compact entry into
`JOURNAL.md`, then re-snapshots.

Guards: refuse with a plain message if TTS is not listening. Snapshots live in
`.journal/` — **never** under `Saves/` or `Mods/`.

### 4.3 The Lua side

`10-hex.lua` — pure functions on the measured lattice: Δx = √3R, Δz = 1.5R, row
offset √3R/2; `disc(r)`, `neighbours`, `toWorld`, `fromWorld`, and the
three-cell footprint of a tri-hex at a given `rotY`. Pure, so `luajit`-testable
with no TTS.

`20-tiles.lua` — spawns via `spawnObjectData` with RotLA's flags (`Locked`,
`Sticky`, `Snap`, `Grid` true; `scaleY 0.5`; `Convex: true`,
`MaterialIndex: 3`, `TypeIndex: 0`). Exposes:
- `Tiles.tint(kind, hex)` — instant, no respawn.
- `Tiles.reskin(kind, url)` — `setCustomObject` + `reload()`, then re-apply
  buttons.
- `Tiles.hub(kind, cell, resource, n)` — via `ttslib.ui.button`, by **name**,
  positioned at one of the three hex centres.

`30-map.lua` — `Map.build(seed)`, `Map.clear()` (destroy by role tag),
`Map.capture()`. `build` must clear first, or a save-then-reload doubles the
map.

`50-api.lua` — the agent contract: short global functions with short arguments,
so one iteration is ~100 tokens of Lua.

`99-Global.lua` — `store.restore` → `registry.check()` → snap points → build if
empty → UI.

## 5. The changelog, two layers

- **Ground truth** — `tts.py diff` on every Game Saved. Catches everything,
  including hand-moved cubes, whether scripted or not.
- **Narrative** — `40-journal.lua` taps `events.on("drop"/"pickUp"/"spawn"/
  "destroy", "*")` and emits a compact record via `sendExternalMessage`
  (arrives as ID 4). Gives ordering and intent that a diff cannot.

Both render **hex-aware**: `hex.fromWorld` turns a float triple back into
`hex(q,r)`, so entries read

```
[15:12] moved  cube 4f2a      hex(1,-1) -> hex(0,2)
[15:13] spawn  tile_jungle x3 hex(2,0) hex(2,-1) hex(1,1)
[15:15] saved  -> TS_Save_131   (+3 -0, 4 moved)
```

Agents read `ttsd.py log --since last`, never the whole file. That constraint is
the point — see §6.

## 6. The three iteration loops

| | Cost | What changes | Mechanism |
| --- | --- | --- | --- |
| **L1 live tweak** | ~100 tok, <1s, no reload | tint, hub label, map reroll | `ttsd exec` one-liner |
| **L2 art change** | ~300 tok, ~2s, no restart | silhouette, texture, per-cell colour | edit `spec/tiles.json` → `tilegen.py` → `ttsd call reskin` |
| **L3 structural** | ~1k tok, TTS reload | new Lua, new components | edit `src/` → `build.sh` → new numbered save |

**L1 is the default; L3 is the exception.** When implementing, prefer any
design that keeps a change in L1. This is the owner's stated priority.

## 9. Risks and open questions

| Risk | Handling |
| --- | --- |
| **UV mapping on the generated `.obj`** is the main unverified step — the diffuse must land square on the top face. | The rule is fixed by measurement (§2.1): planar projection from above, normalised to the bbox. ### The geometry, re-derived rather than copied

`tilegen.py` generates the tri-hex from arithmetic, and the result is
structurally identical to the mesh §2.1 measured: **24 unique vertices** (the
same set, once RotLA's +0.0016 Blender z offset is removed), **44 faces**, 8

faces in three `o` groups, matching RotLA's structure exactly.

Two facts §2.1 left implicit were read off the cached `.obj` and are now the
rule `tilegen.py` implements:

- **v is flipped.** `u = (x-xmin)/width`, `v = 1 - (z-zmin)/depth`. RotLA's
  vertex at `z = zmin` carries `v = 1.0`; the plan said "planar projection from
  above" without fixing the direction, and the other reading mirrors the tile.
- **A +y face winds clockwise in the (x, z) plot.** Every top triangle in
  RotLA's mesh has negative 2-D signed area. Get this backwards and the tile is
  invisible from above and solid from below.

## 12. What the gates found — 2026-09-21, live

The owner loaded `TS_Save_127.json` and it threw an error on load. Both gates
have now been run against the running game; the rig works, and the two things

### Gate §7.4 — the bridge: **passed, with one correction to the protocol**

`ttsd.py status` sees 39999, an ID 3 executes, and the whole command surface

```
reroll      14        tint jungle 7FBF3F   6        rings 2     8
at 0 0      jungle    hub jungle 2 gold    true     lock false  14
```

### Gate §7.3 — the save: **assets confirmed loaded; the visual check is the owner's**

TTS parsed every generated asset. The proof is its own cache, which only gets a

```
Mods/Models Raw/…trihex138ed03fobj.rawm            the tri-hex mesh
Mods/Models Raw/…trihexcolliderdb745737obj.rawm    its collider
Mods/Images Raw/…jungle / deepjungle / river .rawt exactly the three kinds drawn
```

So **the `%20` URL form works** — `--url-style raw` is not needed — and the

### The load error: a `local` that concatenation turned into a landmine

```
Global:(178,10-15): attempt to call a nil value   at A.keyed, Map.clear, Map.build, onLoad
```

`ttslib/01-async.lua` holds its module table in a **top-level `local A`**.
`src/50-api.lua` defined the command surface as `A = {}`, which looks like a
global — and in separate files it would be. A build is a concatenation, so a
top-level `local` stays in scope for every line after it: that assignment
overwrote the library's own module table. `ttslib.async` still pointed at the
real table, so `async.keyed` was callable, but the `A.cancel(key)` on its first
line resolved to the empty one. The error named neither file.

Three changes, so it cannot recur:

| | |
| --- | --- |
| The surface is **`AZ`**, and 50-api.lua lists the names ttslib's locals already hold: `A, S, U, E, R, L, LOG, ASYNC, EVENTS, REGISTRY, Store`. | the fix |
| **`scripts/luacat.py`** — the `cat` that makes a build, plus a lint for exactly this. `build.sh` and `ttsd.py push` both go through it, so they cannot diverge, and neither will ship a build with a shadowed global. | static |
| **`test/boot_spec.lua` loads one concatenated chunk**, not fifteen files. Loading them separately gave every `local` its own scope and hid the whole bug class — all 30 cases passed on the way out. Reintroducing the bug now fails the suite with TTS's exact message. | dynamic |

This is a general hazard for anything built on `ttslib`, not an Amazonia one.

### The hub labels: one stripe per cell, pinned upright

The owner's second finding on the same load. Hub labels rendered turned with
their tile — upside down on a 180-degree tile, diagonal on a 120 — because a
button's `position` *and* `rotation` are both relative to the object, and this
map deliberately uses all six rotations to interlock.

`position` must turn with the tile: the cell it points at moves. `rotation` must
not. `Tiles.hubs` sets `rotation = {0, HUB.facing - tileRotY, 0}`, which pins
every label to one direction whatever its tile is doing. `Tiles.repin`, on the
`rotate` event and keyed per object, redraws after a hand turn —
`onObjectRotate` fires mid-animation, so reading `getRotation()` in the handler
gives the angle the tile is leaving.

**`HUB.facing` is 180, and that is a TTS fact worth keeping.** Cancelling the
tile's spin was not enough: the labels came out uniformly upside down instead of
variously upside down. The tiles were measured level first — `rotX = rotZ = 0`,
`getTransformUp().y = 1`, `getTransformForward().z = 1` — so this is not a
flipped tile. **TTS lays a button's text out with its "up" along the object's
local -Z**, which is away from the default camera, so a button at rotation 0 on
a perfectly upright object reads upside down. Anything in this folder that puts
a label on a flat object needs the same 180. `AZ.hubface(deg)` changes it live,
because "which way is up" ultimately depends on where the camera sits.

The labels are also stripes now rather than boxes (`HUB.width` 1040,
`HUB.height` 165), one per cell as before. Proportions are taste, so
`AZ.hubstyle(w, h, font)` sets all three live — an L1 change. `00-config.lua`
stays the source of truth; a live change is lost on the next reload.

## 12. Second pass — 2026-09-21, after the first table session

The rig worked; what it drew was too blunt to design terrain with. Four changes,
all of them asked for at the table.

### Frontiers

A tile was one flat colour, so terrain could only change at a tile's own rim and
a shoreline could not be drawn at all. `spec/tiles.json` gains two blocks and a
per-kind one:

- **`terrains`** — `jungle`, `deep_jungle`, `river`, each a colour and a grain.
  This is now the single answer to "what colour is jungle": a flat kind of the
  same name inherits its `tint` from here, and a painted one mixes it.
- **`frontiers`** — how a pair of terrains meets. **`reach`** is how far the
  edge terrain pushes in (in hex radii; the apothem is 0.866); **`band`** is how
  wide the crossover is. Keeping those apart is the whole of it — `reach` is
  *how much terrain*, `band` is *how abrupt*. Plus `shore`, a third colour
  painted where the mix crosses half and half, which is what makes a waterline
  read as a beach, and `warp`, which wobbles the boundary off the chord.
- **`paint`** on a kind — per cell, a centre terrain and terrain on any of its
  *outer* edges, numbered the way `hex.DIRECTIONS` numbers them. An edge facing
  a sibling cell blends to that cell's terrain and an override on one is
  refused.

`tilegen.py` renders it as a weighted field rather than a Voronoi fill: per
pixel, the distance in from each edge of the cell the pixel is inside, a
smoothstep about `reach`, and the terrains mixed by weight.

**Two properties the arithmetic is chosen for.** *Registration*: an outer edge's
crossover sits `reach` inside the cell, so the rim itself is pure edge terrain
and a frontier tile butts against a plain one without a step. *Continuity*: an
interior seam uses `reach = 0`, so the mix there is half and half approached
from either cell.

The second one has a trap in it, and the first render hit it. Distance measured
from cell A is exactly minus the distance measured from B, so a warp added to
both pushes the boundary *into* each cell and leaves a visible step down the
seam — the two halves of one shoreline disagreeing. The sign of the warp flips
on the higher-indexed cell, which keeps the two distances exact negatives; the
smoothstep is symmetric about 0.5, so the two mixes then come out identical
pixel for pixel.

`tilegen.py --jobs` fans the diffuses out over the cores (each is independent,
results folded back in sorted order, so `--check` stays byte-exact). The
catalogue went from 5 kinds to 26 and the run from 4 s to under 3.

### The tray

Twenty-one frontier kinds, all at weight 0 — a coast means nothing next to the
wrong neighbour, so they are placed by hand. `src/35-tray.lua` lays one of each
out east of the plate, unlocked, in anchor-local coordinates like everything
else. They carry a third tag, `tray`, and `Tiles.onMap()` subtracts it: build,
clear, reroll and the tile count see the map only, while tint, reskin and lock
still reach the whole table. `AZ.put(kind, q, r[, rot])` is the one-line version
for an agent.

### Only tiles snap

The ask was "triplets interlock, nothing else snaps", and getting there meant
finding out that **TTS has two independent snapping systems**:

| | where it lives | scope |
| --- | --- | --- |
| snap points | data on an object or the table, optionally tagged | per point |
| the grid | Options > Grid, `Grid.snapping` | **global**, every object |

The lattice was blamed first and was innocent. The magnet was the grid, at 3
(Centre) on a hex layout, which pulls every object to the nearest cell centre
and has no tag and no allow-list.

**The save file said otherwise.** `TS_Save_127.json` carries
`"Grid": { "Snapping": false }` and the game loaded from it reported
`Grid.snapping = 3`. Read the live value through the API; the file is where TTS
last wrote state, not what the game is doing.

So: the lattice stays **on** (it is what interlocks the tri-hexes, rotation and
all), `Grid.snapping` is forced to 1 at boot rather than trusted from the file,
and every object that is not a tile has `use_grid` and `use_snap_points` cleared
as it spawns. That last part is what makes "only tiles snap" true without
needing to know whether a tagged snap point spares an untagged object — which
the corpus cannot answer, because every piece in every mod here is tagged.

`AZ.snap(on)` is the lattice, `AZ.gridsnap(on)` is the grid. Both in
[cookbook/10-antipatterns.md](cookbook/10-antipatterns.md#settled-on-the-table).

### Labels off

`HUB.enabled = false` and no kind claims a `hubs` array. The drawing code stays
— the counter-rotation and the 180 baseline above cost a table session — and
`AZ.labels(true)` plus one `AZ.hub` call brings it back. `Tiles.hubs` *removes*
buttons when disabled rather than declining to draw, so the switch takes effect
on tiles already on the table.

### The map was stretched by two along Z, and had been all along

`positionToWorld` scales a local vector by the **mesh**, and a mesh is not
always a unit cube. TTS's `BlockRectangle` measures 1 x 1 x 2, so the anchor
plate at `scale 20 x 0.2 x 17` is **34 deep**, and one local Z unit is 34 world
units rather than 17:

```
a.positionToWorld({1,0,0}).x = 20.00     -- scale.x
a.positionToWorld({0,0,1}).z = 34.00     -- scale.z is 17
a.getBounds().size           = 20, 0.2, 34
```

Every world offset in this rig was converted to anchor-local by dividing by
`getScale()`, so every row of the hex map came out twice as far apart as
`hex.toWorld` said. The tiles never interlocked; it looked like a spacing choice.

`ttslib.layout.basis(anchor)` now measures world units per local unit with three
`positionToWorld` calls — true of any mesh, any scale, and rotation-invariant
because lengths are — and `layout.localOffset` / `layout.worldOffset` are the
conversions the lattice, the tray and `Map.cells` go through.

**The stub was what let it ship.** `harness.lua` multiplied by `scale` alone, so
all 43 cases agreed with the broken arithmetic. The fake object now takes a
`mesh` factor, the Amazonia anchor is built with the measured 1 x 1 x 2, and the
existing "tiles land exactly where the arithmetic says" case fails without the
fix. `ttslib_spec` gained two cases of its own for `basis`.

### One more bug found on the way

`Tiles.data` computed `Locked = (opts.locked ~= nil) and opts.locked or
TILES.locked`. That idiom cannot express false — `true and false or true` is
true — so an explicit `locked = false` came out locked. It had been silently
re-locking unlocked tiles on every reskin; it surfaced as a tray nobody could
pick up.
